Mission Brief

Success & Limits

The time limit ends a session — including a paused one. The action budget is enforced at execution: a refused action never consumes it, and the session ends when the executed actions reach it. Neither limit means the objective was achieved — only a verifier reading the target window can complete a session, and a session without a checkable objective never claims success.

Validate a mission to measure its target window in physical pixels before starting.

Phase Roadmap

  • NF-02 Telemetry & Guardian — implemented in this panel (Telemetry and Guardian tabs).
  • NF-03 Evidence Timeline — implemented in this panel (Evidence Timeline tab: recorded events, frame evidence and read-only replay). It records the action and verification events this build produces, and its replay stays read-only: it never starts, resumes or sends input.
  • NF-04 Benchmark Lab — implemented in this panel (Benchmark Lab tab): validated scenarios, bounded observation runs, persisted results, evidence links and fair comparison. No model or policy is invoked, so model comparison is unavailable; gameplay scenarios are listed as unsupported.
  • NF-05 Controlled Game Evaluation — implemented in this panel (Game Evaluation tab): a validated compatibility registry, per-game readiness checks that refuse an unsafe start, baseline-first observation runs over the NF-04 benchmark lab, retained evidence and a per-game report. An evaluation run is observation-only — it sends no input and claims no objective — so no gameplay capability is claimed for a game.
  • NF-06 Forge Coach — implemented in this panel (Forge Coach tab): evidence-backed findings with provenance, an earliest-recoverable-error analysis, prioritized recommendations and controlled experiments that run through the NF-05 evaluation lab. Approval is bound to the exact configuration, and a result that cannot be compared honestly says so.
  • NF-07 Guarded action path & objective verification — implemented in this panel (Guardian tab): a typed, policy-bounded action is PLANNED as a digest-bound proposal, EXECUTED only after that exact approval re-validates the pinned window, and VERIFIED by reading the window back. A refusal is not a failure, an execution is not a success, and only a verified objective completes a session.

NF-04, NF-05 and NF-06 observe, capture and analyse only: a completed run means its data was recorded, never that an objective was achieved or a game was played. NF-06 invokes no model and trains nothing.
