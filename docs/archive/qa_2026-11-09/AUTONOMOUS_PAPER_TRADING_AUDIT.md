# NovaMarket Autonomous Paper Trading Audit

**Audit date:** 2026-11-09  
**Question:** Does NovaMarket run an autonomous market-data → discovery → strategy → risk → paper execution → monitoring → exit → ledger cycle?  
**Verdict:** **NO — no autonomous paper-trading orchestrator exists.** The manual/API paper chain is functional and broker-free. Autonomous trading is outside the accepted NM-01–NM-14 scope and was not implemented.

---

## 1. Executive answer

NovaMarket can execute a complete **paper** trade when a user/API caller supplies the proposal and approval flow, and the deterministic verifier proves that chain end to end. It does **not** run that chain on its own.

Observed runtime state:

| Signal | Observation | Interpretation |
| --- | --- | --- |
| Runtime monitor | `task_running=true`, interval `3600`, `last_tick=null` | A housekeeping task exists, but it has never completed a tick |
| What the task does | notifications, radar, position ingestion | No discovery→strategy→risk→execution sequence |
| Discovery scheduler | `running=false` | No autonomous candidate scan |
| Live paper orders | 0 | No order was generated by a background loop |
| Live paper fills | 0 | No fill was generated by a background loop |
| Strategy proposals | Stale-data proposals rejected | Risk gate works, but no fresh auto-proposal was produced |
| Broker connection | `broker_connected=false` | No live execution path |
| Autonomous loop documentation | NM-07: no background scheduler; NM-10: no autonomous background loop | The absence is declared design, not an accidental outage |

A `task_running` flag is not a trading loop. No autonomous cycle exists to audit dynamically.

---

## 2. What "autonomous" would require

For this report, an autonomous cycle means all of the following without a user clicking a plan or submitting a proposal:

1. ingest fresh market observations;
2. screen/discover candidates on a schedule;
3. produce forecasts and strategy proposals;
4. obtain an independent NM-08 risk decision;
5. submit only approved proposals to NM-10 paper execution;
6. monitor positions and exits;
7. post resulting fills and fees to the wallet/ledger;
8. repeat on a defined cadence with idempotency, circuit breakers, audit and a kill switch.

NovaMarket has the individual services for steps 1–7. It does not have the orchestrator that composes and schedules them.

## 4. What the runtime task actually does

The runtime monitor in `src/novacontrol/novamarket/service.py` (approximately lines 3496–3600) runs notification, radar and position-ingestion work. It is not a strategy or execution loop:

- it does not call discovery for a scheduled candidate scan;
- it does not create a strategy proposal;
- it does not request a risk decision for a new proposal;
- it does not submit a paper order;
- its `last_tick` is `null` in the observed copy.

The discovery scheduler is separately reported as `running: false`.

The accepted design documents confirm the boundary:

- `docs/NM07_THREE_HORIZON_DESIGN.md` — no background scheduler;
- `docs/NM10_ORDER_MANAGEMENT.md` — no autonomous background loop.

## 7. Why this is not a requirements failure

The accepted NM-01–NM-14 scope requires an integrated workspace and a working paper-execution path. It does not require an unattended autonomous trading loop. The phase documents explicitly describe the absence of a background scheduler and a background order loop.

Accordingly:

- **Requirement status:** not applicable / outside accepted scope.
- **QA status:** BLOCKED for dynamic autonomous-cycle verification because no cycle exists.
- **Safety status:** acceptable; no live path was introduced.
- **Product recommendation:** do not add autonomy without a separately approved design.

---

## 8. Risk of adding autonomy without approval

An autonomous loop would change financial behavior, not just UI. A safe implementation would need, at minimum:

- an explicit cadence and market-session calendar;
- idempotency keys per instrument/session/proposal;
- risk re-evaluation on fresh observations;
- stale-data and provider-failure circuit breakers;
- duplicate-order and partial-fill recovery;
- position monitoring and exit rules;
- a user-visible kill switch;
- audit events for every scheduled decision;
- bounded retries and dead-letter handling;
- a paper-only guard that cannot be disabled by the scheduler.

None of that is implemented by this audit, and none should be inferred from the existing `task_running` monitor.

---

## 9. Required approval before implementation

Autonomous paper trading is an architectural and financial-policy change. It requires explicit user approval before any code is written.

Approval should specify:

1. cadence and market hours;
2. eligible instruments and horizons;
3. maximum orders/notional per cycle;
4. whether risk approval is automatic or human-confirmed;
5. exit policy;
6. kill-switch owner;
7. observability and retention;
8. acceptance criteria and a paper-only safety proof.

Until then, NovaMarket remains a manual/API paper-trading system with a deterministic acceptance chain and no autonomous order generation.

## 11. Final autonomous-audit verdict

**NOT IMPLEMENTED — OUT OF ACCEPTED SCOPE.**

NovaMarket has a verified paper-execution chain and no live broker path. It does not autonomously discover, propose, approve, execute, monitor and exit trades. The runtime task is not a trading orchestrator, and the live QA database contains zero paper orders and zero fills. No autonomous cycle could be dynamically audited; none should be claimed.
