# AGENTS.md — operational learnings for future sessions

## Serving, caching, and the "old UI" trap

- FastAPI serves `/` and `/static` with `_never_cache_headers()` in `src/novacontrol/api/app.py`: `Cache-Control: no-cache, no-store, max-age=0, must-revalidate` + `Pragma: no-cache` + `Expires: 0`. Every HTML/CSS/JS response must carry this trio (pinned by `test_static_html_css_js_are_never_cached` in test_web_api.py, which asserts the EXACT header value across the whole static surface: `/`, top-level assets, every `static/js/` module, and the SVG) — downgrading to bare `no-cache` allows heuristic reuse of pre-header cache entries, and a new asset type that skips the headers fails the test. Cache-bust tokens are auto-injected, never hand-written: `index.html` carries the marker `?v=__NC_ASSET_VERSION__` and the `/` route replaces it with `_static_asset_version()` (a per-request content hash of the whole static tree), so any HTML/CSS/JS edit rekeys every asset URL — mid-session edits included — with no manual `?v=` bump and no restart. Never hardcode a date token in `index.html` (`test_asset_versions_use_server_injected_marker` fails on `?v=2026`) and never delete the marker (`test_index_serves_injected_asset_version` checks the served HTML). A SECOND marker, `__NC_UI_VERSION__`, powers the visible sidebar-footer stamp (`UI v<8-hex>` in `#uiVersion`); the `/` route replaces it with the same content-derived version shortened to 8 chars, so a stale cached page shows an older stamp than a fresh load (`test_ui_version_stamp_uses_injected_marker` in test_web_platform.py guards the marker; `test_index_serves_visible_ui_version_stamp` in test_web_api.py pins that the served stamp equals the injected asset version prefix). When changing the stamp, replace the marker server-side — never put a date/version literal in index.html.
- If the user reports seeing the "old UI": the server can be provably clean (curl the root: sidebar markers + `no-cache` header + newest `?v=` token) while their VS Code/Blackbox embedded browser still shows a stale DOM it restored without refetching. The only fix is fully closing and reopening that tab. The current CSS never hides the sidebar at any width (only shrinks to 200px under 900px) — a sidebar-less render is always a stale DOM, never current code.

## Brain routing

- Routing uses TWO deliberate scratch classifiers, kept apart on purpose: `scratch.scratchable_intent(lower)` (NARROW: returns the intent name — "greeting"/"math"/"time"/"conversion"/"knowledge"/"recommendation" — only for canned local answers; this is the classifier that protects Explore routing) and `scratch._classify` (BROAD: best-effort local intent incl. desktop_control etc., used by the answer engine). Do not unify them — broad routing would send unknown "what is X" topics to a generic local reply instead of Explore research. brain.py's `_keyword_classify` imports ONLY `scratchable_intent` and interprets the name: == "greeting" → CHAT 0.9 first, == "math" → CHAT 0.88 gate right after SELF_IMPROVEMENT and before EXPLORE/PLAN, and the EXPLORE gate fires only when `scratchable is None` (no canned answer) AND a research keyword matched. Do not reintroduce separate `can_answer_directly`/`is_arithmetic_query` imports or a local `_is_greeting` set in brain.py.
- Arithmetic is routed locally through ONE predicate: `is_arithmetic_query(lower)` in scratch.py (`_MATH_EXPR` symbolic + `_WORDED_MATH` spelled-out ops + `_ADD_FORM` + `_WORDED_FUNC_MATH` worded functions like "square root of 256"/"5 squared" + `_FUNC_CALL_MATH` calls like "sqrt(144)"), used by `scratchable_intent`, `_classify`, and the answer engine. Keep ALL math detection in scratch.py via `is_arithmetic_query`, never duplicate matchers in brain.py. `_math_answer` translates word operators to symbols, keeps only the two operands for the "add X and Y ..." form so trailing phrasing never reaches the evaluator, and translates worded functions (`square root of N` → `sqrt(N)`, `N squared/cubed` → `N**2/N**3`).
- `brain.py` no longer contains any answer-capability knowledge — all local-answer detection lives in `novacontrol/brain/scratch.py`, and greetings share one `_GREETINGS` frozenset between `scratchable_intent` and `_classify`.

## Frontend structure and flows

- `/ask` returns one flat envelope `{route, intent, summary, payload}` where `payload` is the handler payload directly — never nested (old `payload.payload`/`decision` wrapping is gone; do not reintroduce). Chat answers can still be full Explore reports; `renderChatResult` delegates report shapes to `tryRenderResearch` in `render-explore.js`, which checks `[data.payload, data, data.report]` (envelope vs flat endpoints). Flat endpoints (`/explore`, `/command/plan`, `/system/health`) return the payload with no `route` key — renderers read `data.payload || data`.
- Chat history survives reloads via localStorage (`novacontrol.chatHistory`, capped at 30 turns): `submitChat`'s `run` `onSuccess` records `{role, text, route}` (assistant text via `chatTextForHistory` in app.js), and init calls `renderChatHistory()` to replay bubbles with `appendMessage` — which was previously dead code and is now the shared history bubble renderer (keep it in sync with the shared markdown rule below). The active panel also persists (`novacontrol.activePanel`, restored by `restoreActivePanel()` which must run AFTER `setupTabs`). `renderChatResult` appends the user's question bubble before the answer page so the thread reads as a conversation; the answer page itself still replaces per-turn (single-turn design).
- `dom.js` owns the only Markdown renderer (`renderMd` + inline `_renderInline`); Chat AND Explore rendering go through it — never add a second renderer. Every free-text path must route through it: chat lead/message (`renderMd`), `appendMessage` bubbles (`renderMd`), `payload.content` (`renderMd`), and list items via `richBullet` (which calls `_renderInline`). A text node still showing raw `**`/backticks means a renderer bypass was introduced.
- Chat-answer text policy has ONE owner: `extractAnswerText(value, fallback)` in state.js (precedence: string → unwrap `/ask` `payload` → `message` → `answer` → `content` → `overview` → `summary` inside payload, then the same fields at top level; trims, scrubs leaked `Payload:`/`Intent:` routing text, returns `fallback` when empty). `textForSpeech`, `cleanSummary` (render-utils.js, adds the "I completed the request." default), `renderChatResult`'s lead, and `chatTextForHistory` (app.js) all delegate to it — never re-derive field precedence at a call site again. `renderGeneralAiPage` (render-panels.js) must never read `payload.message`/`payload.content` as answer text either: the lead (`summary`) is the only place the answer renders, and the section below the heading is STRUCTURE ONLY (suggestions/plan/sections/actions, else the neutral placeholder). Raw field reads there re-leaked scrubbed `Request:`/`Intent:` text (the `payload.message !== summary` guard fired on sanitizer deltas) and duplicated content in the lead+body. The precedence is pinned behaviorally: `ExtractAnswerTextTests` in test_web_platform.py evals the REAL state.js + render-utils.js in Node (skipped cleanly when node is absent) against a 14-row table; a static test also forbids the removed `payload.message || payload.content || data.summary` / `payload.answer || payload.message` chains from returning. Gotcha when embedding JS in such a test: emit each expression with `json.dumps(expr)` so node stores the SOURCE as a string and `eval`s it in the loop — emitting it raw evaluates at array-build time, turning `expr` into the result (then `eval(result)` parses the answer text as code, e.g. "Unexpected identifier 'completed'").
- JARVIS desktop verification (desktop/controller.py): OPEN_APPLICATION polls `_wait_for_window` (Windows: `Get-Process` MainWindowHandle enumeration, matched via `_window_stem`/`_window_matches`) and raises `VerificationError` when no window appears in 8s — a launch that never shows a window now surfaces as FAILED, never "Executed successfully". `_wait_for_window` returns `{}` when the probe ran but nothing appeared (empty dict, NOT False — its annotation is `dict | None` and mypy is clean), `None` only when the probe is unavailable. TYPE_TEXT on Windows stages the exact text via clipboard + Ctrl+V, then `_verify_type_windows` confirms the payload reached the clipboard AND a window is focused before success; apostrophes are PS-escaped by doubling (`''`), NOT backtick-replaced (the old `replace("'", "`")` silently pasted backticks). Probes returning None (non-Windows/unavailable) skip verification rather than fail. Tests stub the OS probes via `ProbingRunner` (tests/test_desktop.py) so nothing touches the real desktop.
- Desktop AND browser automation share one token flow: `/command/plan` mints a single-use, 5-min token (`application.py: _mint_approval/_consume_approval`) and `/command/execute` re-dispatches on the brain intent, so a plan rendered in Chat or the Command panel approves correctly for both devices. The two executors share `_execute_planned_command` (application.py) — token validation lives in each public `execute_*_command` (distinct error wording), the rest (consume → `_workflow_from_plan` → gateway swap → run → mark executed) is one helper taking controller + model classes + `result_label`. Do not fork the two execute bodies again. The in-output "Approve And Run" button in `render-panels.js` must keep posting to `/command/execute` — posting to `/desktop/execute` silently breaks browser plans (it rebuilds the workflow as a desktop workflow). `plan_browser_command` parses navigate/fill-form phrasing (`parse_browser_command` in application_helpers.py) and returns a `not_an_action` envelope without a token when nothing parses.
- `NoopBrowserRunner` (src/novacontrol/browser/controller.py) must mirror `PlaywrightBrowserRunner`'s classmethod `is_available()` — `NovaControlApplication.status()` calls it on the class, and the HTTP tests patch the name with `NoopBrowserRunner`, so missing it fails every `/command/*` TestClient test with AttributeError. Static asset paths: `app.js` is at `/static/app.js` (top level) while its modules live at `/static/js/*.js` — a test requesting `/static/js/app.js` gets 404.
- `run()` in `render-utils.js` owns loading/error/toast/button state for EVERY action — including Explore: the explore button handler calls `run("exploreOutput", "explore", () => streamExploreResearch(topic), "exploreButton", {...})` and `streamExploreResearch` is a pure task that appends `.progress-step` rows under run()'s scan-line and RESOLVES WITH THE REPORT (run() renders it, toasts, unloads the button, and calls onSuccess — which is where `trackExploredTopic`/`recordActivity` live). Never give the streamer its own loading/error/toast/button code again. `run()`'s double-click guard runs AFTER the caller's synchronous prelude — only flows that clear their input before calling `run()` need their own guard first (`submitChat` does because it clears `chatInput`; Explore doesn't clear its input).
- Voice (voice.js): Web Speech fires `onend` after every `onerror`, so an error status that doesn't survive `onend` silently reverts to "Voice ready" — the exact "mic blocked but UI says ready" bug. `state.voiceError` holds persistent failure codes (`not-allowed`/`service-not-allowed`/`security`/`audio-capture`); `onend` re-asserts the error headline while set, and only `onstart` (real mic acquisition) clears it. Transient codes (`no-speech`, `network`) flash guidance but don't hold the error state. Voice notices carry class `voice-notice` and the latest replaces older ones — keep the dedupe if a new call site is added.

## Commands and environment (Windows/Git Bash)

- Pure Python uvicorn app — there is no package.json, never try npm. Server: `python -m uvicorn novacontrol.api.app:create_app --factory --host 127.0.0.1 --port 8000`. `.venv` has an editable install, so edits in `src/novacontrol` are live on restart.
- Tests and mypy need `PYTHONPATH=src`: `python -m pytest tests/ -q` (full suite ≈233 tests + 109 subtests), `python -m mypy src --ignore-missing-imports`.
- Port 8000 is the user's own run target — stray session servers on it cause `[Errno 10048]` when the user starts theirs. Clean up session servers on 8000; use 8001 for previews.
- Explore query layer (src/novacontrol/explore/query.py): `is_relevant` is shopping-aware — `detect_shopping_context` (price/currency/amount or ≥2 commerce words) triggers a stricter gate where qualifier words (`budget`, `under`, amounts) cannot carry relevance alone and a real product token is required, so fiscal pages about "the budget" never leak into "best budget laptops under 500". Function words are stripped from relevance tokens with a fallback to the loose check when no content token exists. `build_search_queries` re-anchors the price phrase (e.g. `under 1000`) because `extract_search_topic` can clip amounts. `_safe_search` in service.py applies `is_relevant` to Wikipedia fallback results too. All pinned in test_explore.py's ShoppingQueryContextTests. The synthesizer's fact-density guarantee (definition-heavy, cause-heavy, and single-fact snippets never degenerate to a bare intro shell for any query kind) is pinned by tests/test_synthesizer.py — do not remove each builder's `_any_facts` fallback, that machinery is the guarantee.
- Git Bash mangles `$` inside double-quoted PowerShell commands (`$p`, `$_` get eaten) — single-quote PowerShell from bash. `Start-Process` detach may time out the tool wrapper while the process survives: then verify port/PID instead of retrying. The `code_search` tool intermittently fails (missing vendored ripgrep) — fall back to `grep`/`sed` via the terminal.
- Ollama auto-detection needs NO env vars: `build_llm_provider_from_environment` (in `integrations/llm.py`) probes `http://127.0.0.1:11434/api/tags` at app boot and hands the shared provider to both Chat and Explore synthesis (wired in `application.py`); detection runs once per boot, so Ollama must be running when the server starts (restart to pick it up). Override/disable with `NOVACONTROL_OLLAMA_URL` / `NOVACONTROL_DISABLE_OLLAMA`. The Ollama base URL must be the ROOT (no `/v1` suffix): `OpenAICompatibleLLMProvider.complete` appends `/v1/chat/completions` itself, and a `.../v1` suffix doubled to `/v1/v1/...` (404) — that regression is pinned by `tests/test_integrations_llm.py`.

## User preferences

- The user reports stale UIs aggressively and values deletion: prefer deletion-first passes and explain what was removed, not just what was added. Changes to the visible UI must be re-verified live after a reload, not asserted.
